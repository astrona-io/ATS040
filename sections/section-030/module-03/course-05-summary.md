# Summary

The Cloud Native Computing Foundation is a vendor-neutral home inside the Linux Foundation. The Governing Board handles business matters, the Technical Oversight Committee sets the technical direction and admits projects, and Technical Advisory Groups give expert help in areas such as security and observability. A project moves from Sandbox through Incubating to Graduated, which shows a mature community and process. It does not show that a project fits a given use or that its API is stable.

Kubernetes has a Steering Committee with elected members for governance. Special Interest Groups own areas such as Node, Network, Storage, Auth and Apps. Working groups coordinate topics across SIGs for a time. OWNERS files name reviewers and approvers, and a change needs `lgtm` and `approved` and passing tests. A Kubernetes Enhancement Proposal gives a large change a design review and tracks a feature through alpha, beta and stable.

Kubernetes makes three minor releases a year. A release team runs enhancements freeze, code freeze, release candidates and the release. The three most recent minor versions get patches, for about 12 months each plus a short upgrade period. Upgrades go one minor version at a time, with the control plane first, within the version skew policy.

The Code of Conduct, based on the Contributor Covenant, applies in all CNCF spaces. Contributions include documentation, issues, reviews, testing and help to other users, and the community meets in Slack, mailing lists, public meetings and GitHub.

- The Governing Board handles business, the TOC handles technology.
- Sandbox, Incubating and Graduated describe maturity and not fit.
- A SIG owns an area, a working group coordinates a topic.
- Three minor releases a year, three minors supported.
