# Summary

Cloud native design favors explicit boundaries, automation, observability and resilience under change. Microservices can support independent ownership and scaling but introduce distributed failure and compatibility costs. Stateless instances externalize durable state rather than removing it.

Event-driven processing separates publication from completion and needs safe retries, acknowledgments and capacity planning. Serverless transfers selected infrastructure responsibilities to a platform while leaving application correctness, permissions and execution constraints relevant.
