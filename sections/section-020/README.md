# Cloud Native Ecosystem and Principles

This section teaches cloud native design; cloud native ecosystem; autoscaling. These ideas help you explain system behavior and choose a suitable approach in a KCNA scenario, and you apply them on a kind cluster.

You will work through Cloud Native Design, Cloud Native Ecosystem, Autoscaling. Each module introduces its goals, teaches the concepts through examples, offers a playground for free practice and a graded lab, and closes with a summary. The section ends with an integration capstone and a knowledge check.

## Learning Outcomes

- Explain loose coupling and microservice tradeoffs.
- Relate resilience, elasticity and external state to replaceable workloads.
- Distinguish serverless execution from the absence of servers.
- Explain asynchronous delivery, retries and idempotency.
- Harden a workload with replicas, probes, requests, a disruption budget and external settings, and run retried work with Jobs.
- Explain how open standards support interoperability.
- Match representative projects to their technical roles.
- Distinguish a specification, implementation and managed service.
- Choose tools from requirements and operating constraints.
- Extend the Kubernetes API with a custom resource definition.
- Explain how the Horizontal Pod Autoscaler computes a replica count from a request-based utilization.
- Distinguish horizontal, vertical and cluster scaling.
- Explain event-driven scaling, stabilization windows and scaling behavior.
- Create an autoscaling/v2 HorizontalPodAutoscaler and tune its behavior.
